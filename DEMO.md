# Демо: запись в один дубль (2–3 минуты)

Демо показывает работу **среды**, а не агента: контракт, честную награду, воспроизводимость и закрытую оценку. По кейсу для демо достаточно скриптовой политики. Обученный аудитор и веб-интерфейс — бонус, баллов они не дают.

Всё считается вживую и офлайн. Если запускать некогда, вывод тура сохранён в [docs/demo/demo_tour.txt](docs/demo/demo_tour.txt) (`make -s demo > docs/demo/demo_tour.txt` его обновляет).

## Подготовка (5 минут, один раз)

1. Запустите Docker Desktop и соберите свежий образ: `docker build -t audit-env .` (на записи не будет ожидания скачивания).
2. Во второй вкладке терминала запустите веб-интерфейс: `make play` (сервер на `http://127.0.0.1:8000`).
3. В основной вкладке: шрифт крупнее (⌘+ два-три раза), окно примерно 140×40 символов, `cd` в корень репозитория.
4. Отключите уведомления (Центр управления → «Не беспокоить»), закройте лишние вкладки браузера.
5. Запись на macOS: ⌘⇧5 → «Записать весь экран» (терминал и браузер попадут в одну запись) → «Записать». Остановить — кнопкой ■ в строке меню; файл `.mov` появится на рабочем столе.

## Запись: одна команда

```bash
make demo-record
```

Скрипт идёт по шагам, а вы переходите дальше по Enter — темп задаёте сами.

| шаг  | что на экране                                                           | что сказать                                                                                                                                                                                                                                                                                                                                           |
| ---- | ----------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| титр | название, одна строка о проекте                                         | «Это воспроизводимая RL-среда для обучения ИИ-аудитора: генератор синтетической бухгалтерии со скрытыми ошибками, контракт reset/step, узкие инструменты, matcher и терминальная награда. Всё вымышлено и работает без сети.»                                                                                                                         |
| 1    | `docker run --rm --network none --cpus 2 --memory 4g audit-env` (~40 с) | «Вся проверка — одна команда в контейнере без сети, в лимитах кейса: генерация эпизодов, 321 тест, независимая проверка данных, фаззинг генератора, базовые политики и траектории.» Пока идёт проверка, можно сказать про официальные определения проверок: все блоки прогоняются в тестах.                                                           |
| 2    | тур из 8 сцен, Enter между сценами                                      | по одной фразе на сцену, см. ниже                                                                                                                                                                                                                                                                                                                     |
| 3    | таблица политик на dev и отложенная оценка                              | «Диагностика: простая сверка не видит FX-ошибок и ошибок периода — разрыв до oracle и есть то, чему среда учит. Обученный аудитор закрывает его на отложенных эпизодах.»                                                                                                                                                                              |
| 4    | открывается браузер с AuditDesk                                         | «Тот же контракт можно пройти руками»: начать эпизод `train/00` → «Счета» → «Загрузить первые 50» (шаг тратится) → «Кандидаты в дубли» (бесплатно; сверху группа «позиции совпадают») → «invoice_id → affected» и «doc_id → доказательства» → «Выводы»: тип «Дубль счёта», сумма, «Сохранить» → «Отправить выводы» → разбор по эталону. 30–40 секунд. |

### Что сказать на каждой сцене тура

1. **reset()** — «Агент видит задачу, манифест, правила учёта и размеры таблиц. Seed и эталон не видит никогда.»
2. **step()** — «Пять узких инструментов. Ошибка — короткий фиксированный код, ввод не отражается. Калькулятор считает только арифметику: `__import__` и несуществующий инструмент `shell` отклоняются, и каждый вызов стоит шаг.»
3. **Скриптовый аудитор** — «Политика листает таблицы и отправляет выводы с суммой и доказательствами. Оценщик: 2 из 8 найдены, ложных нет.»
4. **Награду не обмануть** — «Атака „пометить всё" и случайные догадки получают −1. Повтор правильных ответов снижает награду, правильный ответ без доказательств не засчитывается. Обученный аудитор находит все 8.»
5. **Чистые книги** — «Если ошибок нет, молчание — лучший ответ, а ложные обвинения наказываются.»
6. **Воспроизводимость** — «Тот же seed даёт те же байты, тот же прогон — те же траектории. Перемешивание строк и переименование всех ID не меняет ответ oracle и награду.»
7. **Закрытая оценка** — «В закрытом режиме оценщик живёт в отдельном процессе: политика получает 0 и пустой info, результат есть только в журнале оценщика.»
8. **Подключение жюри** — «Ровно по опубликованному интерфейсу: generate_episode, make_env, score_episode, закрытый режим по episode_dir. Политика видит `accepted: true` и награду 0, а оценщик — TP 2 и return 0.998.»

## Чего не утверждать

- Награда не доказывает пригодность модели для настоящего аудита (это сказано и в кейсе).
- Цифры политик — диагностика; жюри оценивает корректность среды и оценщика, а не награду нашего агента.
- Все компании, люди и деньги вымышлены.

## Полезные команды

```bash
make demo-record       # запись в один дубль: Docker -> тур -> отчёт -> веб-интерфейс
make demo              # тур из 8 сцен без пауз (STEP=1 - по Enter, PACE=2.5 - паузы по 2.5 с)
make demo-steps        # пошаговый проход скриптовой политики по одному эпизоду
make verify            # полная проверка локально
make play              # веб-интерфейс: сыграть за аудитора
```
